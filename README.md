- Atomic local writes
- Idempotent push

- Bounded exponential retry
- Injectable infrastructure boundaries
- Real SQLite integration tests

## How I approach engineering

I prefer architecture that makes change easier rather than architecture for its
own sake.

I use TDD when it helps drive domain design, ADRs when decisions need to remain
understandable over time, and patterns such as Repository, Adapter, Strategy and
Dependency Inversion when they create meaningful boundaries.

I am particularly interested in the problems behind frontend applications:
state ownership, API boundaries, caching, offline behavior, synchronization,
failure handling, observability, performance and deployment architecture.
